## V1 数据设计（2026-08-18）

| 用途 | 数据集 | 规模 | 选它的理由 |
|---|---|---|---|
| **训练干净语音** | DNS Challenge **5** `read_speech` | 1 切片 ≈ 19 小时 | 学术界公认基准；切片可**部分解压**做小规模子集（见下） |
| **训练噪声** | DNS `noise_fullband`（AudioSet + Freesound） | 3 分片 ≈ 14.2 GB | 真实录制，覆盖面远超 MUSAN；按平稳性自动分两组 |
| **房间冲激响应** | DNS `impulse_responses` **+ 本项目合成** | 0.26 GB + 0 | 真实的验泛化，合成的做**受控 RT60 扫描** |
| **受控中文 ASR** | AISHELL-1 test-only parquet 子片 | 398 MB | 安静录音，可同时算 CER 与有参考指标 |
| **真实中文 ASR** | WenetSpeech `test_meeting` | 220 MB | 原始会议录音，只算增强前后 CER，不二次退化 |

### 三套测试集为什么必须分开

| 目录 | 输入 | 参考 | 允许的结论 |
|---|---|---|---|
| `dns_objective` | DNS留出语音 + 留出噪声/RIR | 带混响、无加性噪声 | 去噪质量是否改善 |
| `aishell_controlled` | AISHELL + 同一受控矩阵 | 带混响、无加性噪声 + 文本 | 中文 CER 与质量如何随条件变化 |
| `wenetspeech_real` | WenetSpeech原始会议录音 | 只有人工文本 | 真实会议输入增强前后 CER |

WenetSpeech meeting 本身含噪和混响，不能作为 SI-SDR/STOI/PESQ 的干净参考；
再给它叠加噪声/RIR也只能算压力测试。V1 因此不再让一套数据承担三个互相冲突的职责。

### 为什么只取 20~30 小时，不下完整数据

DNS 完整语料约 892 GB（其中 `read_speech` 就有 299 GB），下载解压训练都不现实。
真正让小子集够用的是**在线动态混音**：训练时才实时抽取干净语音 × 随机噪声 ×
随机 RIR × 随机 SNR 做卷积混合，不预先离线混好存盘。
20~30 小时基础语料经过动态混合，可产生近乎无限的声学组合，
足以支撑轻量模型收敛且不易过拟合。

### 为什么噪声要区分稳态 / 非稳态

这是"传统 DSP vs 神经网络"这条对照的**核心抓手**：

- **稳态**（风扇、机房白噪声、车载空调）：谱统计平稳，MCRA 类噪声估计跟得上，
  谱减/维纳/MMSE-LSA 表现好且算力极低；
- **非稳态**（键盘敲击、关门、餐具碰撞、babble）：统计特性瞬变，
  传统方法无法快速跟踪噪声谱，失效或产生明显音乐噪声 —— 神经网络该赢的地方。

DNS 的噪声文件**不带平稳性标注**（只有 RIR 有 T60/isReal 那类元数据），
所以用 [`rtse.dsp.stationarity`](../src/rtse/dsp/stationarity.py) 从信号本身算：
时间轴平滑 → 帧能量去趋势 → 取 P95−P05 动态范围。
本地在构造上已知平稳性的合成噪声上验证过（见
[`tests/test_stationarity.py`](../tests/test_stationarity.py)）：
white / pink / hum 稳定判为稳态，babble / cafeteria / keyboard 稳定判为非稳态，
**跨 12 个随机种子判决一致**。

> ⚠️ **已知限制**：极低频主导 + 慢调制的噪声（如 `car` 型）判决**不稳定**，
> 实测跨种子动态范围 0.67~16.22 dB，横跨门限。试过限带到语音频段规避——
> 反而更糟（babble 被压到与之重叠）。这个限制可以接受，因为本模块的用途是
> 给几万个文件**分组**而非给单个文件下权威判决。
>
> 门限 9.0 dB 是在合成噪声上标定的，真实录音分布更连续。
> notebook 里会打印两组的数量，比例悬殊（比如 9:1）就该调门限。

### 为什么 RIR 要合成 + 真实两种都用

| | 优势 | 用途 |
|---|---|---|
| **合成 RIR**（镜像源法） | 参数完全可控，可精确指定房间尺寸、吸声系数、麦克风位置 | 生成精确 RT60（0.2/0.4/0.6/0.8 s）做**严格量化扫描** |
| **真实 RIR**（DNS 实测） | 含非均匀漫反射、墙面材质不对称吸收、麦克风频响失真 | 检验真实声学环境下的泛化，**避免"仿真过拟合"** |

真实 RIR 会先按**实测 RT60**分桶，只和同一 RT60 档位的合成 RIR 比较。
桶外的极端 RIR 不混入主表，避免把“真实性差异”和“混响更强”混成一个变量。

## 两套受控测试集的分层

固定预生成（**不能在线随机**，否则每次评测的噪声段和 SNR 都不同，
前后两次的 CER 没有可比性）。训练集则相反，必须在线随机混音。

| 维度 | 取值 | 格数 |
|---|---|---|
| SNR | −5 / 0 / 5 / 10 / 15 dB | 5 |
| 噪声平稳性 | 稳态 / 非稳态 | 2 |
| RIR 来源 | 合成 / 真实（按实测 RT60 匹配） | 2 |
| RT60 桶 | 0.2 / 0.4 / 0.6 / 0.8 s | 4 |

噪声/RIR矩阵共 **80格**，另加1个 clean→clean 无害性格。冒烟版每套81条，
正式版每套405条。
WenetSpeech 真实集另按短/中/长三档取30条冒烟或300条正式样本。

### SNR 阶梯的理由

- **−5 ~ 0 dB**（压力测试）：重度淹没，最容易暴露**过抑制**——
  听着安静了但 ASR 断崖式下跌，这正是前端与后端 trade-off 最清晰的地方；
- **5 ~ 10 dB**（典型远场）：日常办公、会议室远场拾音的典型信噪比，
  工程落地价值最核心的区间；
- **15 dB**（轻噪）：评估**无害性**——好的增强算法在信噪比已经不错时，
  不该引入额外相位失真或削减高频，导致 CER 反而劣化。

### RT60 阶梯的理由

- **0.2 s**：小型吸音良好的房间/录音间
- **0.4 ~ 0.5 s**：标准现代会议室与中小型办公室
- **0.8 s**：大型未做声学装修的教室、走廊、高挑大堂

混响造成**时域拖尾**：前一个音素的反射能量覆盖后一个音素，
严重破坏 ASR 声学模型的特征边界。V1 扫描 RT60 是为了测**混响条件下的去噪鲁棒性**，
不是宣称模型能够去混响。

> 测试集里同时记录 `rt60_nominal`（标称）和 `rt60_measured`
> （用 [`rtse.dsp.rt60`](../src/rtse/dsp/rt60.py) 的 Schroeder 反向积分实测）。
> 记两个是因为踩过坑：`make_rir` 的镜像阶数曾被写死，
> 导致标称 0.9 s 的 RIR 实测只有 0.63 s（[`ISSUES.md`](../docs/ISSUES.md) I-22）。
> 标称值是**请求**，实测值才是**事实**，报告里该引用后者。

（STFT 逐帧一致、dBFS 标定精确到 0.000 dB）。这里有偏差，
训练出来的模型拿回本地就会掉点，而且两边单独看都"没问题"，极难定位。

### ✅ DNS5 语音切片可以"只下一部分"

DNS5 的干净语音是 `split` 切成的 `.tgz.partaa` ~ `.partau`，官方用法是全部
下载后 `cat *.part* | tar xz`。但 **gzip 是顺序流格式**——只下第一片再直接
`tar -xzf` 也能解出前面一大批**完整**文件，走到被切断处报 `Unexpected EOF`，
那是预期的，忽略即可（`fetch_dns(..., partial_ok=True)` 就是干这个的）。

用 HTTP Range 取前 80 MB 实测（服务端返回 206，Range 可用）：

- 解出 **231 个完整 wav**，全部可正常读取
- 格式 **48 kHz 单声道**（下游 `read_audio` 会重采样到 16 kHz）
- 时长 min 1.1 / 中位 4.9 / max 10.3 秒，231 个文件共 18.3 分钟
- 据此推算整片（5.24 GB）约 **19 小时**，正落在 20~30 小时的目标区间

> 🐛 **抓到第二个真 bug，而且是致命的**：DNS5 的文件名形如
> `book_00000_chp_0009_reader_06709_0_seg_1_seg1.wav`，
> 说话人 id 藏在 `reader_XXXXX` 段里。原来的 `stem.split('_')[0]`
> 会对**每个文件**返回 `"book"`，**所有语音归成一个说话人**，
> 说话人划分彻底失效、指标虚高。改用 `re.search(r'reader_(\d+)', ...)`，
> 并在 notebook 里加了自检断言（提取出的说话人数落在合理区间才继续）。
>
> 这 231 个文件切出 **47 位说话人**——注意这只是 80 MB 前缀的采样，
> **不是整片的说话人总数**（整片约 1.5 万个文件，说话人会多得多）。

## 实跑中修掉的问题

全部是**只有真跑才会暴露**的，详见 [`ISSUES.md`](../docs/ISSUES.md)：

| 编号 | 问题 | 后果 |
|---|---|---|
| **I-24** | 直流分量把功率统计撑歪 | 实测 SNR 与标称对不上；汇总均值看不出来，按档位排开才暴露 |
| **I-25** | 按扩展名判断压缩格式 | `read_speech.tgz.partaa` 被判成 bzip2，语音**解出 0 个文件** |
| **I-26** | 截断的解压被当成成功 | 噪声分片只解出 1156/7739 却报 `[done]`，训练数据**少了 85%** |
| **I-28** | `sys.modules` 缓存 | 换了代码包还在跑旧模块，报错行号对不上，误导人反复重传 |

配套加了这些防护：magic bytes 判格式、解压标记记录文件数、下载标记记录字节数、
`sys.modules` 清理 + 打印实际加载路径和改动时间、lbzip2 并行解压、
SNR 单调性断言、校验从磁盘读 `index.json` 而非内存变量。

> `N_SPEECH_SHARDS` 现在**断言只能为 1**：DNS5 语音是 split 切片，
> gzip 头只在 `partaa` 里，`partab` 及之后是裸的流中段，单独解压必然失败。
