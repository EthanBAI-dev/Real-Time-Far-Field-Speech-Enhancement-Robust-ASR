## 方法学结论（不随数据集作废）

### M-01 · SI-SDR 与可懂度经常方向相反，所以必须直接测 CER

单通道降噪能显著改善信噪比与听感舒适度，但**几乎不改善、甚至损害可懂度**
（Loizou 等人反复验证过的经典结论）。原因是增益函数在压制噪声的同时
不可避免地衰减了与噪声谱重叠的弱语音成分——尤其是能量低、但对区分音素
至关重要的辅音。SI-SDR 只看能量比，对"少了一个辅音"几乎无感。

**这正是本项目的核心问题之所在**：如果降噪必然改善 ASR，这个项目就没什么可做的。
所以指标表必须把 ΔSI-SDR 和 ΔCER 并列，用来展示两者相关性有多弱，
而不是拿语音质量指标去代理下游任务表现。

> 旧数据上已经用真实 ASR 验证过这个方向性结论（不只是 STOI 这类代理指标），
> 但**具体数字在新数据上需要重测**。

### M-02 · 冲激噪声打垮 MCRA 的机制

MCRA 的核心假设是"**噪声是谱的下包络，语音是其上的瞬态**"，
靠跟踪平滑功率谱的局部最小值判断哪些频点当前没有语音。
键盘敲击这类**宽带、高能量、极短时**的冲激，在它看来和语音起始一模一样：
能量突然远高于局部最小值 → 判为"有语音" → 噪声估计**不更新** →
这段噪声完全不被抑制。与此同时增益函数仍在轻微衰减真实语音，净效果就是收益被吃掉。

**这条机制解释从未被推翻**（被推翻过的是它造成多大损失的量化断言）。
它是新数据集"按平稳性给噪声分组"这个设计的直接理论依据：
稳态噪声上 DSP 应该够用，非稳态噪声上它该失效，
而这正是神经网络最有说服力的立足点。

单帧追踪能直接看到这个误判过程，是可视化失败案例的一号素材。

### M-03 · 三次验证失败的教训：能用代码逻辑证明的，别用有噪声的信号去猜

修 I-21（测试集文本比音频长）时，"验证修复是否生效"这件事本身失败了三次：

1. 第一版查了**混响后**的参考音频——混响拖尾被误判成"还在说话"；
2. 第二版改查混响前的干信号——仍然误报 61%，因为真实录音说完最后一个字
   到文件结束往往没多少静音余量，而能量 VAD 的 hangover 时长与之相当；
3. 最终改成**纯代码逻辑的结构性断言**（`assert clean.size <= seg_len`）——
   生成循环的重试逻辑已经保证了这个不变量，数学上可证明，零声学假设。

**教训**：只要能用确定性的代码逻辑证明的结论，就不该退而求其次用一个
有噪声的启发式信号去间接验证。VAD 本身没错，错的是用它去回答一个
数学上已经有答案的问题。

配套的另外两条（详见 [`ISSUES.md`](ISSUES.md)）：

- **I-22**：`make_rir` 的镜像阶数写死成 12，导致 RT60 超过 0.6 s 后完全失效，
  标称 0.9 s 实测只有 0.63 s。教训是——**写完一个测量工具，第一件事是拿它
  去量自己已知答案的东西**。这个 bug 藏了很久，因为 T60 一直被当成
  可信的**输入参数**，从来没被当成待验证的**输出**检查过。
  新数据集因此同时记录 `rt60_nominal` 和 `rt60_measured`。
- **I-23**：`.gitignore` 少写一个前导斜杠，把 `src/rtse/data/` 和
  `src/rtse/models/`（含 CRN 模型定义）整个排除在仓库外，
  GitHub 上的代码 clone 下来根本跑不了。教训是——**配置的"过度生效"
  比"不生效"危险得多**，不生效会立刻报错，过度生效则安静地做了你没要求的事。

## 新数据集上的五个预设问题：已答四个

| # | 问题 | 结论 |
|---|---|---|
| 1 | 稳态 vs 非稳态上 DSP 与 NN 的差距？ | ⚠️ **与假设相反**，specsub 在非稳态上反而有帮助（F-10②），但样本量小 |
| 2 | 跨语种泛化成立吗？ | ❌ **不成立**。DNS 英文训练的模型在中文会议录音上 CER 恶化 +0.18~0.19（F-10） |
| 3 | 合成 vs 真实 RIR 差多少？ | ⏸ **无法归因**——两层同时差了混响强度这个变量（F-09） |
| 4 | 降噪对 CER 是帮忙还是帮倒忙？ | ❌ **帮倒忙**，且**模型越大越差**（F-10①） |
| 5 | 15 dB 下会不会反而变差？ | ✅ 会。specsub −0.004 基本无害，但 crn-lite **+0.152**（F-10） |

> 第 2 条的否定结论有一个重要限定：它说明**这个模型**没有跨语种泛化，
> 不等于"跨语种泛化这条路走不通"。F-10① 的诊断指出模型是在**过抑制**
> （在录音棚级干净语音上训练，学到的"干净"标准远高于会议录音的实际水平），
> 这是**训练数据与目标域不匹配**的问题，不是语言差异的问题。

## F-09 · 真实 RIR 的混响远比合成扫描强，两者不能直接对比

**测量条件**：2026-08-17 Colab 实跑 `01_data_prep.ipynb`，
DNS5 `impulse_responses_000` 解出 60248 条真实 RIR，
用 `rtse.dsp.rt60`（Schroeder 反向积分）逐条实测。

| RIR 来源 | RT60 |
|---|---|
| 合成（镜像源法，标称 0.2 / 0.4 / 0.6 / 0.8 s） | 实测 0.194 / 0.476 / 0.709 / 0.910 s |
| **真实（DNS5）** | **0.09 ~ 5.28 s，中位数 2.20 s** |

**现象**：真实 RIR 的中位混响时间（2.20 s）**是合成扫描上限（0.91 s）的 2.4 倍**，
最长的到 5.28 s。也就是说测试集里"合成 RIR"和"真实 RIR"这两层，
面对的根本不是同一个声学难度。

**这构成一个混淆变量**。测试集设计这两层的本意是回答
"合成 RIR 上测出来的成绩比真实 RIR 好多少"（即量化"仿真过拟合"），
但现在这个对比同时掺了两个因素：

1. 合成 vs 真实的**声学特性**差异（本来想测的）；
2. RT60 约 0.2~0.9 s vs 约 2.2 s 的**混响强度**差异（不小心引入的）。

两者叠在一起，测出来的差距无法归因。**直接说"真实 RIR 上掉了 X dB，
所以仿真过拟合有多严重"是错的**——那个差距里有多少来自"真实房间更复杂"、
多少来自"真实房间就是更混响"，分不开。

**怎么修（未做，记录为已知缺口）**：真实 RIR 已经逐条测了 RT60，
按 RT60 分桶后**只取落在 0.2~0.9 s 区间的**去和合成层对比，
这样混响强度对齐，剩下的差异才可归因于声学真实性。
桶外那些高混响的 RIR 不必丢掉——它们本身是有价值的压力测试档位，
但要单独成层、单独报告，不能和合成层混在一张表里比。

**对本项目叙事的意义**：这是"分层设计要控制变量"的一个具体案例。
测试集分层的价值在于**每个维度能单独扫描**，一旦某两层之间同时差了两个因素，
那一层的结论就退化成"有差异"，而说不出"差异来自哪里"。
这跟 I-22（标称 T60 不等于实测）是同一个主题的两面：
前者是标称值不可信，后者是**两组标称值不可比**。

## F-10 · 降噪对中文 ASR 全面无益，神经网络损害最大

**测量条件**：2026-08-18，`rtse-eval --cer-per-cell 2`，40 条/方法，
faster-whisper `small`。训练数据是 DNS5 英文语音，评测是 WenetSpeech 中文会议录音
（跨语种设计，见 [`notebooks/README.md`](../notebooks/README.md)）。

| 方法 | CER | ΔCER |
|---|---|---|
| clean（干净上界） | 0.293 | — |
| noisy（不处理） | 0.646 | — |
| specsub | 0.640 | −0.005 |
| wiener | 0.699 | +0.053 |
| mmse-lsa | 0.727 | +0.082 |
| crn-nano | 0.821 | +0.176 |
| **crn-lite** | **0.836** | **+0.190** |

### 三个值得注意的现象

**① 神经网络比传统 DSP 差得多，而且模型越大越差。**
crn-lite 的验证 SI-SDR（14.19 dB）高于 crn-nano（13.16 dB），
CER 却更差（+0.190 vs +0.176）。**训练指标与下游任务负相关**——
这是 M-01 那条"必须直接测 CER"最直接的证据。

根因在 I-30 的诊断里已经看到：把**干净参考本身**喂给 crn-lite，SI-SDR 是 −12 dB。
模型在 DNS 录音棚级干净语音上训练，学到的"干净"标准远高于会议录音的实际水平，
于是把会议室固有的背景声连同部分语音成分一起抹掉了——**过抑制**。
SNR=5 dB 那一档 ΔCER 高达 **+0.355**，正是典型远场办公信噪比区间，
也就是工程上最该有用的地方，它损害最重。

**② 与设计假设相反：specsub 在非稳态噪声上反而有帮助。**

| 方法 | 稳态 | 非稳态 |
|---|---|---|
| specsub | +0.043 | **−0.053** |

M-02 预测的是"DSP 靠 MCRA 跟踪噪声下包络，稳态噪声上够用、非稳态上失效"。
实测方向反了。**但样本量只有每格 20 条，这个差异未必稳健**，
不足以推翻 M-02 的机制解释——那个机制在单帧追踪上是能直接看到的。
要坐实需要更大样本，以及**按噪声子类**（而不只是二分类）拆开看。

**③ 唯一有帮助的场景是 SNR=−5 dB 的重度淹没。**
specsub 在那一档 ΔCER 是 **−0.154**。此时不处理的 CER 已达 1.006
（错误数超过字符数，识别基本崩溃），降噪把它拉回了一些。
**信噪比越差，降噪的边际价值越高**；信噪比尚可时，降噪引入的失真超过它去掉的噪声。

### 局限（这条结论目前是方向性的）

- **40 条/方法**，`STRATA` 只有 20 格，且 4 档合成 RT60 被折叠成一档
- **干净上界 CER 已达 0.293**——ASR 在这份自发会议语音上本就很弱，
  基线偏高会压缩方法间的区分度
- 只测了一个 ASR、只跑了一轮，无方差估计

### 对本项目叙事的意义

这条结论把项目的核心张力摆到了台面上：**为语音质量优化的降噪算法，
不一定对语音识别有帮助，可能反而有害**——而且**训练指标越好的模型，
下游可能越差**。

它同时给出了一个明确的工程判断依据：这套前端**不应该无条件接在 ASR 前面**。
可行的做法是**按输入 SNR 做条件调度**——只在极低信噪比（≈ −5 dB 及以下）
启用降噪，其余情况直通。这不是回避失败，是从数据里读出来的部署策略。

## F-11 · 模型缺失"无害性"：训练里从没见过干净输入，于是对什么都下重手

**测量条件**：2026-08-18，用录音棚级干净语音（`data/demo/chinese_news.wav`）
作为**训练域代理**测 crn-lite——它的性质接近 DNS `read_speech`，
不像 WenetSpeech 会议录音那样自带噪声，因此能把"域不匹配"和"模型本身坏了"分开。

| 输入条件 | 输入 SI-SDR | 输出 SI-SDR | Δ |
|---|---|---|---|
| white 噪声 SNR=5 | 5.00 | 6.30 | **+1.29** |
| babble 噪声 SNR=5 | 5.54 | 6.92 | **+1.39** |
| white + 混响 0.3 s SNR=5 | 4.99 | 7.77 | **+2.78** |
| **干净参考直接过模型** | 128.42 | **7.27** | **−121.15** |

**模型没坏。** 在有噪输入上它稳定改善 1.3~2.8 dB，方向完全正确。

**但它对干净输入下了重手**：一个本该近乎透传的场景，输出只剩 7.27 dB SI-SDR。
换句话说，**不管输入多干净，它都按"很脏"来处理**。

### 根因：训练分布里根本没有"干净"这一档

查 `MixConfig` 的默认值：

```python
snr_range: tuple[float, float] = (-5.0, 20.0)
noise_prob: float = 0.98
```

- **SNR 上限是 20 dB**，模型**从未见过接近无噪的输入**；
- `noise_prob=0.98`，只有 2% 的样本完全不加噪。

于是模型没有任何理由学会"输入已经干净时应当放手"。它学到的映射是
"无论看到什么，都往录音棚级干净去推"——这在训练分布内是最优策略，
拿到分布外就变成**无条件的过抑制**。

值得注意的是，同一个文件里 `reverb_prob=0.5` 的注释已经写明了这个道理：
*"训练集里必须保留一部分近场干净样本，否则模型会把去混响当成无条件要做的事，
在本来就没混响的输入上产生过处理。"* ——**混响这一维做对了，噪声这一维没做**。
同一个陷阱，防住了一个，漏了另一个。

### 这解释了 F-10 的全部现象

| F-10 的观察 | F-11 的解释 |
|---|---|
| SNR=15 时 crn-lite ΔCER **+0.152** | 输入越干净，过抑制的损害越大 |
| SNR=5 时最差（**+0.355**） | 典型远场信噪比，输入尚可，却被当成很脏来处理 |
| SNR=−5 时几乎无害（+0.048） | 输入确实很脏，重手处理接近合适 |
| 模型越大越差（lite > nano） | 容量越大，越能把"推向录音棚级干净"这个目标执行到底 |

### 修法（代码已做，待重训验证）

1. **把 SNR 上限从20提高到35 dB，并把恒等样本从2%提高到10%**——
   让训练分布覆盖"几乎不需要处理"的情形；
2. 或者显式加入一批 **clean→clean 的恒等样本**，直接教会模型透传；
3. 评测侧保留 15 dB 那一档作为**无害性检验**（本来就是这么设计的，
   现在证明这一档确实抓到了问题）。

### 教训

**训练分布的边界决定了模型的行为边界。** 缺失的不是"更多数据"，
而是**分布的某一端**——这类缺陷在训练/验证指标上完全看不出来
（验证集同分布，也没有干净样本），只有在分布外的真实输入上才暴露。

"无害性"必须像其他能力一样**被显式训练和显式评测**，不能假设它会自动成立。

## F-12 · 一套测试集不能同时充当干净参考、受控中文实验和真实会议泛化

旧设计把 WenetSpeech `test_meeting` 原始会议录音再叠加 DNS 噪声与 RIR，然后同时
用于 CER 和有参考声学指标。I-30 已证明会议原音本身含噪与混响；这会产生三个问题：

1. 它不是 SI-SDR/STOI/PESQ 所要求的干净参考；
2. 二次加噪/混响是压力测试，无法代表原始真实会议场景；
3. 真实 RIR 中位 RT60 2.20秒，而合成上限0.91秒，来源与强度同时变化。

V1 将职责拆开：DNS留出集负责客观质量，AISHELL-1负责受控中文CER，WenetSpeech
原始会议录音只负责真实场景CER。真实RIR先按实测RT60分桶，再与同档合成RIR比较。

这不是“换一个更容易的数据集”，而是让每个结论都有满足前提的数据证据。
